# asdTranslator

一个双向沟通翻译器：帮 ASD / 阿斯伯格用户解码 NT（神经典型者）话里的潜台词，
把自己想说的话翻译成对方更容易接住的版本，以及在开口之前先把混乱的内部状态梳理清楚。

**它不是矫正工具。** 它假设沟通断裂是双向错配，不是你单方面的缺陷。

---

## 为什么是「双向」

设计基石是 Milton (2012) 的**双重共情问题**：ASD 与 NT 之间的理解困难是
*相互的*，而不是 ASD 一方的能力缺失。Crompton et al. (2020) 用信息传递链实验证实了这一点——
全 ASD 链和全 NT 链的信息保真度没有差异，只有**混合链**会衰减。

这直接决定了三件事：

1. 翻译必须是双向的（解码 NT + 表达给 NT），只做单向就是在暗示谁需要被修正
2. 你的原话**永远不会**被标记成「错误」，只会标注「在 NT 语境里可能被读成什么」
3. 每个改写建议都同时显示 **gain 和 cost**——软化措辞不是免费的，它会损失精确性

## 四个模块

### 1. 听懂对方（解码）

把对方说的话拆开：

- **NT 惯用语匹配** — 34 条词条，8 个类别（软性拒绝、模糊承诺、反语、情绪信号、隐含请求、社交仪式、包裹式批评、边界信号）
- **每条给多个候选解读 + 置信度 + 适用条件**，不给唯一答案
- **模糊量词量化** — 14 条（「尽快」≈ 1–2 个工作日、「回头」≈ 15 分钟–3 小时），并给出追问话术
- **三层拆解** — 把整段话分成 事实 / 情绪 / 行动诉求

```
输入：这个方案挺好的，我们回头再说吧。你先别急着改，我尽快给你反馈。

「回头再说」[软性拒绝]
   · 65% 已经决定不推进了，这是委婉收尾
     适用: 你已完整讲过方案、对方没有追问任何细节、也没有约下次时间
   · 35% 确实需要更多信息或需要向上请示
     适用: 对方追问了细节、主动约了下次时间、或提到需要谁点头

「尽快」≈ 1–2 个工作日
   追问: 「尽快是指今天之内，还是本周内？我想排一下顺序。」
```

置信度是**校准过的候选**，不是判决。同一句话在不同关系里含义可能完全相反，
所以解码结果永远带免责说明。

### 2. 把话说出去（表达）

**只标注，不自动改写。** 这是硬性约束，写进了测试。

10 条直白度标记（绝对化否定、直接判错、无主语祈使、信息密度过高、缺开场/收尾、意图未标注、过度自我弱化……）。
每处标记必须带 `keep_note`——说明**在什么场合保留原话是对的**：

```
⚑ 「是错的」直接判错 [high]
   keep_note: 在技术评审、代码 review 等已建立「对事不对人」共识的场合，
              直接判错通常是合适的，不必软化。
   L1  「我这边理解不太一样」+ 具体差异        cost: 把判断降级成视角差异
   L2  「我担心 X 会导致 Y，不知道是不是我漏了什么？」
                                            cost: 较长；用担忧代替判断，给对方台阶
```

社交缓冲件（开场 5 / 缓冲 10 / 收尾 5 / 三档拒绝）**默认全部关闭**，
每个都可以单独打开并显示它的代价。改写只在你显式点击组装时才发生。

### 3. 梳理思路（表达前）

入口**不是**「你现在感觉怎么样」。

述情障碍在 ASD 群体的患病率是 49.93%（NT 为 4.89%，RR = 6.50，Kinnaird et al. 2019），
其中「识别情绪」（DIF）和「描述情绪」（DDF）是两个独立的大效应维度。
直接问情绪对将近一半的用户是无效入口。

所以三步流从**躯体锚点**开始：

```
Step 1  先不用管情绪。哪些身体感觉符合你现在的状态？（16 项，可多选，可全不选）
        躯干 5 / 感官 4 / 行为冲动 4 / 认知 3

Step 2  胸口发紧 → 候选情绪：恐惧 / 愤怒 / 焦虑 / 被压迫
        「说不上来」是有效答案，不是失败。

Step 3  你需要什么？（12 类）
        更多时间 / 书面确认 / 对方停止某行为 / 信息解释 / 被听见不需要建议 /
        改变环境 / 独处恢复 / 重新协商范围 / 承认或道歉 / 可预期性 / 拒绝 /
        我还不确定我要什么  ← 这是合法终点，不是未完成
```

产出一段可直接用的话，**外加三分支预案**（顺利 / 僵持 / 被拒），
因为只给「顺利」剧本等于把风险全留给用户。

### 4. 记录

存偏好、对话人档案（同一个词在不同人嘴里含义不同，可以按人覆盖）、历史条目。

**不存任何评分。** 数据层显式拒绝写入社交表现分数。

## 红线层

Jang et al. (CHI 2024) 测出 GPT-4 对自闭症用户有三类系统性伤害：诱导 masking、
建议披露诊断、过度乐观预设。论文 §5.2 的结论是——**只靠 prompt engineering 消不掉**，
必须有独立于生成过程的检测层。

所以 `engine/guardrails.py` 独立于 LLM 存在，任何输出（规则引擎的和模型的）都要过它：

| 规则 | 级别 | 为什么 |
|---|---|---|
| 身体行为建议 | **block** | 「保持眼神接触」不可执行，且要求同时管理内容和身体表现会显著加重认知负荷 |
| 伪装诱导 | **block** | masking 与抑郁、耗竭、自杀风险相关（Cage & Troxell-Whitman 2019；Cassidy 2018） |
| 替用户决定披露诊断 | **block** | 披露是有真实职业风险的个人决定，工具无权代做 |
| 单一乐观预设 | warn | 不给失败预案等于把风险留给用户 |
| 缺陷化措辞 | warn | 把差异说成毛病 |
| 能力评分 | warn | 量化社交表现会强化自我监控，正是 masking 的机制 |
| 过度确定的读心 | warn | 把猜测说成事实 |

红线同时用**字面串**和**正则**两种模式匹配。正则是必需的：
「告诉**对方**你有阿斯伯格」被拦而「告诉**同事**你有阿斯伯格」放行，
这条红线就形同虚设。

**20 条对抗性用例 + 5 条良性用例**作为 CI 门禁（`self_test()`），
既防漏检也防误伤——红线过紧会让工具在用户最需要它的时候拒绝工作。

## 跑起来

```bash
cd asdTranslator
./run.sh                 # 自动建 venv、装依赖、启动
```

打开 http://127.0.0.1:5111

### 可选：接入大模型

不配也能完整使用——规则引擎离线工作。配了之后解码和改写会更贴合语境。

```bash
export ASDT_LLM_API_KEY="sk-..."
export ASDT_LLM_BASE_URL="https://api.openai.com/v1"   # 任何 OpenAI 兼容端点
export ASDT_LLM_MODEL="gpt-4o-mini"
```

模型输出**同样要过红线层**，违规会带着具体的违规原因反馈给模型重试；
重试仍失败则回退到规则引擎结果。

### 测试

```bash
./venv/bin/python tests/test_guardrails.py     # 27 项
```

## 结构

```
app.py              Flask 路由（17 个接口）
config.py           配置、默认偏好、场景定义
database.py         SQLite 数据层
engine/
  base.py           公共结构：Reading / Hit / Flag，JSON 缓存，句子切分，重叠去重
  decode.py         NT → ASD 解码
  compose.py        ASD → NT 标注（analyze 只标注 / apply 才改写）
  clarify.py        躯体锚点 → 情绪 → 诉求 三步流
  guardrails.py     红线检测 + 对抗性评测集
  llm.py            可插拔 LLM，带违规反馈重试
data/               6 个 JSON 知识库，改完调 /api/reload 热重载，不用重启
tests/              27 项测试
```

知识库全是 JSON，改词条不用碰代码。热重载：

```bash
curl -X POST http://127.0.0.1:5111/api/reload
```

## 设计红线（UI 层）

这些不是偏好，是约束：

- 没有红色报错样式——你的表达不是 bug
- 没有任何形式的评分或进度条
- 原文永远可见，改写永远是并列展示而不是替换
- 缓冲语默认全关，打开时显示代价
- 每个建议都说明「保留原话在什么场合是对的」
